# 0.6.3 code audit — 2026-11-01

## Fixed findings

- **P1: malformed network packets.** Timer, ping, vote, repair and shield-drain
  callbacks now validate packet shapes, types and finite numbers before mutation.
- **P1: missing sender checks.** Authoritative timer/vote/repair state requires the
  host; ballots cannot impersonate another actor. Shield drain must be positive,
  target a defence drone and originate from a covered player. Negative drain can
  no longer charge arbitrary batteries.
- **P2: wasted Death Protection charges.** Match native hit rejection and saving
  grace, and apply protection after shields have reduced the final damage.
- **P2: regeneration scaling/cap errors.** Apply healing multipliers before
  fractional accumulation, avoid a second scaling pass and respect the HP cap.
- **P2: incomplete sprint reduction.** Scale the full native sprint deduction,
  including the sprint-speed surcharge. Accumulate fractions too small for one
  float deduction. Jump/slide costs and authored base fields remain native.
- **P2: stale Charge Efficiency.** Existing stations pick up team purchases and
  config changes before charging; each station retains its own authored rate.
- **P2: ineffective battery purchases.** Stop at the effective +100% bonus or the
  lower configured level cap.
- **P2: invalid Black Market purchases.** Reject nonexistent/composite modifier
  IDs and unknown catalogue kinds before spending currency.
- **P2: incoming pings while disabled.** Remote markers respect the ping toggle.

## Validation

The audited build passed 856 controlled Unity assertions, 96 controlled network assertions,
26 currency-unit/scope regressions and 21 saved/deferred drone-set regressions. All 135 Harmony targets resolved against the installed game;
89 embedded resources matched their source hashes. Native sprint IL and the
shield/Death Protection prefix order were checked. Build: zero warnings/errors.

The portable [network suite](../../tests/NetworkTests/README.md) is included in the
repository. The broader Unity fixture uses local game/engine references and is
not distributed with the mod. These checks are not a live multiplayer or Proton
certification.

## HUD, wallet and delivery corrections (2026-11-02)

- J toggles quests independently of Tab; starts hidden. Map statistics and quests use a
  shared measured sidebar, wrapping and PgUp/PgDn pagination rather than overlapping upgrades.
  Actual 480x270 world-space HUD geometry with no explicit canvas camera is covered.
  Modifier names clear quota glyphs; descriptions track the projected level number without
  inheriting its scale. Font previews cover 1920x1080, 2560x1600, 1280x960 and 3440x1440.
- Quest rewards convert dollars to wallet K units once, rounding up as native extraction does.
  Economic payout scaling is scoped to StateComplete/StateTaxReturn; quest rewards remain
  outside that multiplier even during an extraction callback. Prior inflated saves are not repaired automatically.
- Ping Anywhere is required for every locally placed ping. Ping Info only enriches labels.
  Teammates/tumbles classify as Player, transmit an avatar view ID and track movement.
- Link sets reserve a saved pair ID when bought. Native shop purchases only increment delivery
  counts: owned keys appear later during truck ItemAdd. The delivery patch consumes saved
  A/B reservations in either spawn order, including reused instance suffixes. Existing
  unpaired halves cannot steal the next purchase's partner. Cached prompt names use the
  installed game's actual ItemAttributes.Update API (GetItemNameLocalized was removed).
- Shared Heal Power uses `2-(1-p)^level`; shared charging drain uses
  `max(0.05,(1-p)^level)`. Default level-three values: 1.578125x and 0.512x respectively.

Portable suites: `dotnet run --project tests/NetworkTests -c Release`,
`dotnet run --project tests/CurrencyTests -c Release`,
`dotnet run --project tests/LinkTests -c Release` (.NET 10).

Controlled purchase/delivery adapters, engine joint physics and API resolution were checked.
This does not certify live multiplayer item delivery, complete quest progression or Proton.
The existing client-trust design for personal quest money requests remains an explicit limit.
